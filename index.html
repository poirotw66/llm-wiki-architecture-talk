S02Hook

一個 VPN 問題，四個都「正確」的答案

「我是台南分公司的正式員工，今天換了一台公司管理的新筆電。登入 ExampleVPN 時出現 DEMO-455，該怎麼處理？」

A · Legacy VPN Guide

DEMO-455 通常是 credential validation failure。

B · Zero Trust Policy

分公司正式員工 + managed device 改走 Entra ID + Conditional Access。

C · Service Desk FAQ

FAQ 說先檢查帳密，但未區分新舊架構。

D · Incident Postmortem

37 / 50 rollout cases 與 incomplete device compliance 相關。

RAG 把四份都找回來，仍不代表答案已經解決。

歷史小語料 A/B，不是 LLM Wiki 實驗。作用是建立 bridge：我們不是沒做 retrieval，而是 retrieval 之後還有 knowledge lifecycle 問題。

下一個問題不是「能不能找回來」，而是「找回來以後，哪個 claim 對這個人是真的？」

S05Architecture

Query Time 還承擔了什麼？

Raw DocumentsA/B/C/D 都可被找回

LLM resolves every timeapplicability / conflict / supersession / evidence strength
Answer每次 query 都重走知識迷宮

這不是檢索不到，而是把知識工程工作丟到每一次 query 當下。

S06Definition

把 Knowledge Work 搬到 Update Time

Raw Documents來源變更
Knowledge Compilation整合 scope / conflict / evidence
Review / Validation工具、人審與回歸問題
Published Knowledge可發布的 knowledge artifact
Agent查詢時使用較穩定的知識層

LLM Wiki = Knowledge Contract for Agents。Markdown 只是載體。

S07Source tension

S13Validation boundary

Structural Valid ≠ Semantic Correct

structural lint 可以抓

missing-summary-v2：lint exit 1，斷鏈與缺 source summary 被抓出。

但不等於語義正確

stale-v2：lint exit 0，但內容仍少了新來源要求的更新步驟。

工具檢查必要，但無法單獨保證知識仍符合最新來源。

S14Enterprise boundary

Knowledge Layer 接到 Teams Agent / WeKnora

Teams Agent

Knowledge tells the Agent what is true. Business workflow tells the Agent what to do.

Intent → FAQ / Knowledge / Ticket → Clarification → Citation → Feedback

WeKnora

Open-source ecosystem 也從 RAG 擴展到 Wiki、Revision、RBAC、Audit、Knowledge Management。

少量 FAQ 用普通 RAG 即可；頻繁版本、部分取代、多人維護、provenance / ACL / lifecycle 才開始值得做 Knowledge Compilation。

S15Takeaways

三句帶走

  1. Not every RAG failure is a retrieval failure.
  2. LLM Wiki moves knowledge integration from query time to update time.
  3. Treat enterprise knowledge like a releaseable software artifact.

企業知識不只是內容。它也需要編譯、測試、版本與發布。
