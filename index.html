S08LLM role

LLM 是 Knowledge Change Proposal Engine

Source changenew policy, FAQ, incident note
LLM proposesimpacted pages, conflict candidates, mutation plan, regression queries
Gatesdeterministic checks + semantic validation + human review
Active knowledgepublished only after approval

LLM proposes knowledge changes. It does not become the source of truth.

S13Validation

Structural Valid ≠ Semantic Correct

Structural lint catches

broken links
missing source pages
malformed metadata
required fields

Still needs semantic validation

outdated claim
wrong applicability
partial supersession
unsupported inference

結構檢查必要，但無法單獨保證知識仍符合最新來源。

S14Boundary

Knowledge Layer 接到 Teams Agent / WeKnora

Teams Agent

Knowledge tells the Agent what is true.
Business workflow tells the Agent what to do.

Intent / Issue → FAQ / Knowledge / Ticket → Clarification → Citation → Feedback

WeKnora

Open-source ecosystem 也正在從 RAG 擴展到 Wiki、Revision、RBAC、Audit、Knowledge Management。

不要重造所有 RAG。要分清楚 knowledge infrastructure 與 business workflow。

S15Close

三句帶走

  1. Not every RAG failure is a retrieval failure.
  2. LLM Wiki moves knowledge integration from query time to update time.
  3. Treat enterprise knowledge like a releaseable software artifact.

企業知識，不只是內容。它也需要編譯、測試、版本與發布。
